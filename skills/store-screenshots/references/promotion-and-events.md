# Event and promotional assets

Verified 2026-10-17. Read only the requested platform's section. Event media promotes a specific timely experience; do not substitute generic listing artwork or apply Header/screenshot rules indiscriminately. Prepare the event brief, locales, eligibility/access conditions, dates/timezones, deep link, asset mapping and review plan before production. Reuse capture/export guidance from [video-production.md](video-production.md) where appropriate.

## Apple In-App Events

| Placement | Image/video pixels | Ratio |
| --- | --- | --- |
| Event card | 1920 × 1080–3840 × 2160 | 16:9 |
| Event details | 1080 × 1920–2160 × 3840 | 9:16 |

Images: JPG/JPEG/PNG. Videos: MOV/M4V/MP4, 30 or 60 fps; 500 MB maximum per media file. Card audio: AAC stereo 256 kbps/44.1 or 48 kHz; details also support PCM. Silent tracks are supported. The creative-spec table gives event videos 15–30 seconds; do not apply Header's 5-second minimum. Compose both orientations independently, with a consistent story and no clipped focal content.

Sources: [Event media/audio](https://developer.apple.com/help/app-store-connect/reference/in-app-events/in-app-event-media-and-audio-specifications), [creative specifications](https://developer.apple.com/help/app-store-connect/reference/app-information/creative-assets-specifications).

In app → In-App Events → Create (+), set a unique internal name, event name (≤30), short description (≤50), long description (≤120), badge and both media placements. Add localizations, region availability, discoverability/start/end times, deep link, purpose/priority and required-purchase information. Test that the link opens the event's real content. The setup guide allows events from 15 minutes to 31 days and discoverability up to 14 days before start. Inspect actual app/region eligibility and overlapping-event limits rather than inventing a worldwide launch time.

Source: [Offer In-App Events](https://developer.apple.com/help/app-store-connect/offer-in-app-events/offer-in-app-events/).

Preview both placements and languages, then submit the event and assigned assets when authorized. Approval precedes visibility; verify schedule and selected placements as well as [asset state](apple-asset-library.md). Report prepared/submitted/approved/live separately. Follow current [event creative guidance](https://developer.apple.com/app-store/in-app-events/) when deciding whether the experience qualifies; a routine evergreen app description is not automatically an event.

## Google Promotional Content

Eligibility differs from ordinary store listings: current guidance says all games, and apps eligible for Premium growth tools. Confirm console access. Describe a real event, notable update or offer with clear user benefit, access conditions and a matching in-app schedule; do not submit generic or duplicate evergreen promotion. Offer/value rules differ from baseline listing text, so consult the destination's specific requirements instead of importing a universal ban on prices/discounts.

Primary image: 1920 × 1080, JPG/24-bit PNG. Required even with video. Keep critical content within the published static-image safe area (15% top, 10% sides, 20% bottom); verify actual Preview and Spotlight overlays. No border frames, store badges, fake controls or added text/brand logo, except the source's narrow product/third-party collaboration exceptions. Spotlight imposes additional limits, including ≤1 MB image and shorter taglines.

Animated assets use **Lottie**, not SVG or an arbitrary MP4: 16:9, ≤200 KB, 60 fps, ≤6 seconds, seamless loop. Animation safe margins differ: 15% top, 20% sides/bottom. Use event-specific visual content, a static fallback and accessible description; follow text/logo exceptions in the live source. Do not promise Lottie production if an appropriate exporter/validator is unavailable.

Video must be landscape, public/unlisted, embeddable and without ads/monetization claims; localize visuals/text/audio. Show the specific promotion's real experience. Only the first 30 seconds autoplay; that is not a total-video duration limit. Tagline ≤80 and description ≤500 characters; Spotlight adds stricter text limits. Read the live source for the exact locale and offer requirements before writing final copy.

Source for eligibility, formats, safe areas and content rules: [Promotional Content quality guidelines](https://support.google.com/googleplay/android-developer/answer/12929944?hl=en).

Configure in the app's available Promotional Content flow; record type, schedule/timezone, target countries/locales, conditions, deep link and image/animation/video mapping. Inspect actual fields rather than inventing a fixed UI path. Preview, submit and verify resulting status only when authorized. Keep this separate from [Play Shorts](google-additional-assets.md), normal YouTube previews and custom listings.
