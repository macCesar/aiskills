# Estilo de redacción

Formula el propósito en una frase antes de redactar. “Al terminar, un supervisor podrá identificar qué rondines quedaron pendientes” permite elegir ejemplos, detalle y vocabulario. “Hablar sobre un sistema de rondines” deja abierta la pregunta que el artículo debe resolver.

| Si el lector necesita… | Enfoque | Cómo desarrollarlo |
| --- | --- | --- |
| Elegir qué hacer con un problema de su negocio | Divulgación orientada a una decisión | Abre con lo que está en juego para el negocio. Muestra cómo cambiaría el trabajo y qué condiciones favorecen cada opción. |
| Entender un concepto de IA, programación o una herramienta | Explicación | Define el término en lenguaje cotidiano. Muestra una acción y su resultado en un ejemplo. |
| Reproducir una implementación en Titanium, Laravel o una API | Tutorial técnico | Abre con el problema y el resultado esperado. Incluye requisitos, pasos y una comprobación cuando el lector vaya a seguirlos. |
| Considerar la postura de un autor | Opinión o ensayo | Plantea la pregunta, presenta la postura y distingue los hechos de la interpretación. Conserva la voz y los matices del autor. |

Decide cuánto detalle incluir según la tarea. Para un dueño de negocio, explica que una API permite que el pedido de la tienda llegue al sistema de inventario. Para quien tiene que conectar esos sistemas, describe qué datos se envían y cómo se comprueba que la operación se completó. Si el artículo sirve a ambos públicos, explica primero la consecuencia para el negocio y reserva la implementación para una sección con su propio subtítulo.

## Cuando el blog también da a conocer un servicio

Da al lector motivos para reconocer su situación y entender el valor de resolverla. Por ejemplo, si ventas confirma un cambio de cantidad y almacén sigue preparando el pedido anterior, muestra la consecuencia de trabajar con dos versiones. Explica cómo sería el trabajo si ambas áreas consultaran el mismo pedido confirmado. Habla de una integración si las herramientas pueden intercambiar ese dato o de un sistema a medida si el flujo requiere permisos y aprobaciones que las herramientas actuales no cubren.

Presenta el servicio real dentro de la explicación, en el punto donde su aportación ya se entiende. Di qué diseñaría, conectaría o desarrollaría la empresa. Si basta con un ajuste sencillo a la herramienta actual, explica cuándo seguiría siendo suficiente. Usa un enlace oficial y expresa los beneficios como resultados que el diseño busca conseguir. Atribuye las mejoras medidas únicamente a casos con evidencia. Para cerrar, puedes indicar qué situación amerita una conversación y qué ejemplo de la operación serviría para empezarla.

Elige la forma según el material. Una escena antes y después, una comparación, un caso documentado y una explicación de costos pueden ayudar al mismo público. Conserva los pasos para piezas cuya promesa sea ejecutar una tarea. Una prueba breve puede apoyar una decisión si su resultado cambia la recomendación.
